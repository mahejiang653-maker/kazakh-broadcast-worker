# Дәулет v3.9：减少额外韵律重置，保留自然句子结构

用户反馈 v3.8 的整体 AI 感仍重。本轮继续优化现有免费 Edge `kk-KZ-DauletNeural`，针对新闻请求的上下文和 SSML 路径修改；没有新增模型、依赖或付费服务。v3.8 的 DSP 完整沿用。

## 定位

1. 普通新闻路径已是单个 prosody span，但紧凑的四、五句编号新闻会因三句上限在条目中间再次请求 Edge；合成器因此看不到完整条目的上下文。
2. 点击「分析整篇」并提交手动情绪设置后，旧代码会切回另一套短语／词级韵律渲染器。真实 D 样稿产生 16 个 prosody span，并绕过新闻模式专用的 320 ms 编号停顿规则。旧音频仍可能由标点产生停顿，不能把“未插入显式 break”说成“完全没有停顿”。自动的分析反馈提示不等于这条手动路径。
3. v3.8 根据长句字数在逗号、分号和冒号追加固定 45/75 ms break，这不是语义理解。v3.9 保留原标点，由原生句子结构处理这些内部停顿。

上述是代码能控制的机械感来源。Edge 本身的发声纹理、语义重音和句尾曲线仍是另一层限制；低频能量减少不能证明整体 AI 感降低。

## 修改

- `app/lib/daulet-news.ts`：版本改为 `daulet-news-v3.9`；先按完整句子识别编号条目，包括同一段里连续粘贴的条目；普通分块仍保持完整 1–3 句。仅紧凑的编号条目允许 4–5 句在同一请求中，且不超过 90 词、650 字符。此阈值只决定是否合并完整单位，不按字符截断；下一编号始终开启新条目。超长句的分号／冒号保护、专名与数字处理、请求上限保留。
- SSML 明确使用 `<p>` / `<s>` 表达段落与完整句子，每个请求只有一个外层 prosody span。编号留在其后面的陈述句内，继续插入 `320ms` break；保留末尾 release。移除字数驱动的 45/75 ms 内部 break，保留全部原始逗号、分号和冒号。
- `app/api/synthesize/route.ts`：手动情绪选择始终进入专用新闻渲染器。选择以匹配文本长度加权，只产生非常小的条目级方向变化，不再生成每个词／短语的额外 wrapper。孤立编号和不匹配文本不影响条目语气。
- `tests/daulet-news.test.mjs`：补充完整四、五句条目、下一编号边界、原生句子结构、八种情绪的变化上限和编号停顿检查。
- 本文档。其他声线、页面、故事与混合语言路径不改。

## 参数、DSP、拼接和缓存

标准新闻界面为 1.00×、pitch/volume 0 时，原基础 rate `1.01303`（SSML `+1.30%`）、pitch `+0.82%`、volume `+0.00%` 沿用；原有轻量语义方向与密度减速继续生效。真实 B 新版最终为 rate `+0.80%`、pitch `+0.96%`、volume `+0.10%`。手动情绪附加 rate 因子范围 -0.005 至 +0.003，pitch -0.12% 至 +0.14%，volume -0.05% 至 +0.06%，再按覆盖比例和强度缩小。

没有增加低频削减、压缩、混响、降噪或假呼吸。DSP 仍是 v3.8 的跟踪低脉冲／共振 EQ、55 Hz 高通与一次全文响度增益，详见 [v3.8 记录](daulet-tracked-pulse-v38.md)。状态跨 chunk 保持，末尾 release、原有接缝 280/420 ms、边缘渐变和单次 160 kbps MP3 编码不变。B/D 紧凑条目从两次请求变为一次，因此不再需要其中的一处外部音频拼接。数字、日期、名称与 `ә ғ қ ң ө ұ ү һ і` 的处理沿用。

版本号进入已有音频缓存 key，刷新页面后重新生成才会使用 v3.9。已下载的 v3.8 文件不会变化。0.95× / 1.05× 仍保留。

## 真实 A/B

2026-10-03，用相同的四组源文本、声线和界面参数，分别执行 v3.8 与 v3.9 的实际 API 代码，获取真实未编码 PCM；两路都经过同一个 v3.8 DSP 和同一个 MP3 编码器。两版因上下文和 SSML 不同而分别合成，不是同一份 PCM 的处理对照，也不做时间拉伸。B/C/D 均是虚构测试稿。

| 样稿 | Edge 请求 旧→新 | prosody span 总数 旧→新 | PCM 时长 旧→新 | 第一编号安静区 旧→新 | MP3 LUFS 旧→新 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 普通短句 | 1→1 | 1→1 | 9.400→9.400 s | 无编号 | -22.40→-22.40 |
| B 国际新闻 | 2→1 | 2→1 | 33.970→34.635 s | 360→365 ms | -22.19→-22.14 |
| C 数字日期长句 | 3→3 | 3→3 | 49.195→48.960 s | 350→350 ms | -22.92→-23.10 |
| D 手动情绪路径 | 2→1 | 16→1 | 34.165→34.670 s | 355→365 ms | -22.21→-22.16 |

安静区按 5 ms RMS 窗、-50 dBFS 阈值测量，包含模型自身停顿，不等于 SSML break 的精确长度。所有输出无 PCM 削波；新版 MP3 真峰值 A/B/C/D 为 -4.39 / -3.67 / -2.44 / -3.69 dBTP。A 的变化很小。请求数、韵律区块和接缝减少是客观变化，不是人工真人感评分。

试听页内嵌原始全文 MP3，可离线打开；为公平比较，播放器仅用静态音量衰减每对较响的一路，与较低的实测 MP3 LUFS 对齐。MP3 文件本身不改，音频包同样保留原始网站输出，未改时长或动态。因两版时长不同，切换时相同秒数只是近似位置；建议从头比较整条新闻。

另测过强 SSML contour 校准：Edge 接受并改变了基频，但改变原有声线与曲线，未采用。没有把参数变化等同于自然度提升，也没有冒充人工盲听；实际真人感需核对 A/B。

## 速度与验证

没有增加运行时 DSP 成本或并发数。曾试过更大的完整条目合并上限，C 从三次请求降为两次，但其中一个约 45 秒的音频块使当次生成从约 9.07 s 增至 16.57 s，未采用；最终保守上限让 C 保持三块。最终收集的一次 C 生成耗时 24.51 s，补充计时还遇到一次上游超时，说明不能仅凭减少请求数宣称线上加速或保证没有耗时差异；网络和长块的延迟需要分开看。B 当次约 9.13→9.72 s，D 约 1.58→1.83 s；这些单次耗时不是稳定性能结论。

进一步为两版都创建未使用过的 C 文本变体，交错生成两对，均保持三块：第一对包含首次端点获取，旧→新为 23.48→19.73 s；第二对复用端点，旧→新为 2.775→2.794 s。未见固定的新版耗时增长；样本量有限，不能保证所有设备与网络的性能。重复原稿的三轮 C 耗时区间仍为旧版 7.47–14.87 s、新版 14.64–15.22 s，完整保留此不利结果和网络阶段记录，不把它隐藏成稳定提速结论。

生产构建和 22 项回归通过，覆盖哈萨克字母、数字日期与名称、长稿、所有十三个编号、文本顺序、DSP 正常周期保护、失败／取消处理和原有页面／地球模块。新闻 helper 严格 TypeScript 检查通过；完整 route 的五个既有类型诊断与 v3.8 相同，没有新增，未顺带修改无关模块。

## 限制与回滚

本轮修正额外制造韵律重置的代码路径，无法重训练 Edge 的哈萨克语韵律、恢复真人语义理解或重建声带振动。喉音、气泡音和逐音节朗读仍可能来自原模型。继续加强 EQ 不会自动产生真人重音，可能损失 Дәулет 的男声厚度；本轮因此没有加重 DSP。

可按同一提交回滚三个代码／测试文件和本文档至 v3.8；不需要更换引擎或依赖。

SSML 结构参考：[Microsoft 句子与段落说明](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-structure)、[prosody 说明](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-voice)。实际兼容性已通过本项目使用的 Edge 通道生成验证，不以付费 Azure API 代替现有引擎。
